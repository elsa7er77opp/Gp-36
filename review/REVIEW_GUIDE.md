# GP36 annotation review guide (Phase 1d)

The review package is `review/phase1c_2026-10-30/`, generated by `tools/run_forensics.py`. That script only reads the raw data.
You edit **only** `ANNOTATION_AUDIT.csv`. Never edit the raw images or labels in `GP36_Dataset`.
If a label must change, write the corrected label file under `review/corrected_labels/<source>/<original name>.txt` and put its path in `corrected_label`.

## What to open
| Folder in `sheets/` | What it shows | What to decide |
|---|---|---|
| `exact_duplicates/` | Byte-identical images side by side, each with its own labels. Conflicts come first. | Which annotation is correct, or a merged correction. Keep **one** copy and set the other copy to `REJECTED` with decision `duplicate`. |
| `near_dup_cross_split/` | Perceptually similar pairs across the original splits or sources, largest hash distance first. | Are they the same scene? This calibrates the near-duplicate threshold. Note the first sheet where pairs stop being the same scene. |
| `ghpot_all/` | All 191 crowd-sourced potholes | Box correctness, missing potholes, boxes that are not potholes |
| `ghsb_all/` | All 370 speed-bump video frames | Missing bumps (especially the empty frames `lin061–lin090`), and whether the boxes are consistent |
| `rf8_random_*` | 48 + 48 random Roboflow images (seed 0) | Estimate the general label quality of the main source |
| `regression_cases/` | Known historical cases | Confirm the documented findings |

Colours: **red = pothole, blue = speed bump**. Box numbers are drawn inside each box, and no text is drawn above boxes.
Each caption shows the sample, the size, P (pothole count), B (bump count) and the leakage group id.

## Columns you fill in
* `review_status`: one of
  * `PASS`: labels are correct and complete;
  * `FIXED_AND_VERIFIED`: you supplied a corrected label and checked it on an overlay;
  * `QUARANTINED`: unsure, ambiguous, or needs a second opinion; kept out of v3 for now;
  * `REJECTED`: unusable, or a duplicate copy; kept on disk, never deleted;
  * `NEEDS_REVIEW`: looked at it, but undecided.
* `review_decision`: a short reason code, e.g. `duplicate`, `missing_pothole`, `not_a_pothole`, `crosswalk_not_bump`, `box_too_loose`, `ok`.
* `reviewer`, `review_date` (YYYY-MM-DD), `review_notes`.

`auto_status` is only a machine suggestion. `AUTO_CHECKS_PASSED` does **not** mean PASS: only a person sets PASS.

## Ontology questions to settle first (they decide many rows at once)
1. Painted zebra crossing with **no** raised profile: `speed_bump`, or background?
2. Raised pedestrian crossing / speed table: `speed_bump`?
3. Rumble strips, and road humps with no paint: `speed_bump`?
4. Potholes on unpaved or dirt surfaces (e.g. `pothole_208`): `pothole`, or out of scope?
5. Asphalt patches, manholes, cracks: always background, never `pothole` (project rule).
6. Box style when one pothole has sub-cavities: one box around the whole defect, or one box per cavity?

Write the answers into `CLASS_MAPPING.md` before mass-reviewing, so that every reviewer applies the same rules.
